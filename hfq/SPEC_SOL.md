# HFQ 港股 LV2 行情分析终端设计规格

## 1. 文档目的

本文档定义 `hfq` 下港股 LV2 行情分析软件的产品范围、界面结构、数据模型、Futu OpenD 接入方式、异常处理和验收标准。

当前阶段只完成设计，不编写程序代码。后续实现应以本文档为基线，参考 `hfq/screenshot` 中的界面能力与信息密度，但不复制原软件的品牌、图标或专有素材。

## 2. 产品定位

软件定位为运行在本机的港股盘口与逐笔分析终端，面向需要观察日内成交、买卖盘深度和价格走势的用户。

首个验收标的是腾讯控股：

- 用户输入代码：`HK.0700`
- Futu 标准代码：`HK.00700`
- 名称：腾讯控股
- 市场：香港
- 数据源：本机 Futu OpenD

软件只提供行情展示与分析，不包含真实下单、撤单、账户资产操作或自动交易。

## 3. 设计目标

1. 在单个工作台内同时展示证券概况、分时、K 线、逐笔成交和十档盘口。
2. 复现参考截图的高信息密度与多面板结构，同时改善视觉层级、可读性和窗口适配。
3. 使用 Futu OpenD 作为港股行情的唯一数据源，不使用模拟行情掩盖连接或权限错误。
4. 对 `HK.0700`、`0700`、`700` 等常见输入进行安全、可预测的代码归一化。
5. 明确区分实时数据、缓存数据、收盘数据、无权限和连接失败等状态。
6. 软件在 Windows 本机启动，通过浏览器访问，避免引入复杂桌面运行时。
7. 后续可扩展到其他港股，但第一阶段只以 `HK.0700` 完成端到端验证。

## 4. 非目标

第一阶段不实现以下能力：

- 实盘或模拟交易。
- 账户登录、持仓、资金和订单管理。
- A 股逐笔委托还原或交易所原始订单号追踪。
- 对 Futu 未提供数据的推测、补齐或伪造。
- 多用户、云端部署和公网访问。
- 新闻、研报、财务报表和选股器。
- 对参考软件品牌、名称、图标和受保护素材的复制。

## 6. 总体信息架构

主窗口采用桌面终端式布局：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏：品牌 / 代码搜索 / OpenD 状态 / 数据时间 / 刷新                 │
├──────────────┬───────────────────────────────────────┬───────────────┤
│              │ 证券摘要：名称、代码、价格、涨跌、OHLC、成交额        │
│ 自选列表     ├───────────────────────────────────────┤ 十档盘口      │
│              │                                       │               │
│ - 腾讯控股   │ 主视图标签：分时 / 日K / 盘口分布     │ 卖十 … 卖一  │
│              │                                       │ 最新价        │
│              │ 图表区                                │ 买一 … 买十  │
│              │                                       │               │
├──────────────┴───────────────────────────────────────┴───────────────┤
│ 底部数据区：逐笔成交 / 统计摘要 / 过滤器 / CSV 导出                  │
└──────────────────────────────────────────────────────────────────────┘
```

### 6.1 顶栏

顶栏包含：

- 产品名称：`HFQ LV2 Terminal`。
- 证券代码输入框。
- 加载按钮或回车搜索。
- Futu OpenD 状态指示：
  - 已连接。
  - 正在加载。
  - 无行情权限。
  - OpenD 未启动或未登录。
  - 数据源错误。
- 当前数据对应的市场时间。
- 手动刷新按钮。

### 6.2 左侧自选列表

第一阶段默认包含：

| 用户显示代码 | 内部代码 | 名称 |
|---|---|---|
| HK.0700 | HK.00700 | 腾讯控股 |

列表项显示代码、名称、最新价和涨跌幅。选中项使用高亮边框和背景，不使用只依赖颜色的状态表达。

### 6.3 证券摘要

显示以下字段：

- 名称与标准代码。
- 最新价。
- 涨跌额与涨跌幅。
- 今开、最高、最低、昨收。
- 成交量、成交额。
- 买一、卖一和价差。
- 数据更新时间。
- 市场状态。

港股颜色采用常见习惯：

- 上涨：红色。
- 下跌：绿色。
- 平盘：中性色。

### 6.4 主视图

主视图提供三个标签页。

#### 分时

- 最新价折线。
- 均价线。
- 昨收基准线。
- 下方分钟成交量柱。
- 横轴覆盖港股连续交易时段，并对午间休市做视觉区分。
- 鼠标悬停显示时间、价格、均价和成交量。

#### 日 K

- 日 K 蜡烛图。
- 成交量。
- MA5、MA10、MA20。
- MACD DIF、DEA 和柱体。
- 默认加载最近 120 个交易日。
- 提供前复权、后复权和不复权选项；默认前复权。

#### 盘口分布

- 以价格为纵轴展示十档买卖盘数量。
- 买盘和卖盘采用不同颜色。
- 条形长度按当前十档最大数量归一化。
- 显示买卖盘总量与委比。

第一阶段不承诺复现截图中的历史委托地图。Futu 常规行情接口提供的是当前盘口和逐笔成交，不应将其表述为交易所完整历史委托流。

### 6.5 十档盘口

从上到下展示：

1. 卖十至卖一。
2. 最新价、涨跌幅和价差。
3. 买一至买十。

每档字段：

- 档位。
- 价格。
- 委托数量。
- 委托笔数；仅当 Futu 返回该字段时显示。
- 相对数量背景条。

若账户只有较低等级行情权限，界面必须明确显示实际可用档位，不能补造十档。

### 6.6 逐笔成交

表格字段：

| 字段 | 含义 |
|---|---|
| 时间 | Futu 返回的市场时间，保留毫秒 |
| 方向 | 主动买、主动卖或中性 |
| 价格 | 成交价 |
| 数量 | 成交股数 |
| 成交额 | 价格乘数量或 Futu 返回值 |

交互：

- 默认按时间倒序显示最近 500 笔。
- 可切换时间正序。
- 可筛选全部、主动买、主动卖和中性。
- 可设置最小成交股数。
- 大单阈值默认取当前样本成交量的 90 分位数，并允许用户修改。
- 点击记录后，在分时图上定位对应时间。
- 可导出当前筛选结果为 UTF-8 CSV。

### 6.7 汇总统计

汇总卡片包括：

- 样本成交笔数。
- 总成交股数。
- 总成交额。
- 主动买入股数与金额。
- 主动卖出股数与金额。
- 中性成交股数与金额。
- 主动买卖量比。
- 样本成交均价。
- 最大单笔成交。

所有统计必须标明其统计范围，例如“最近 500 笔”，不能让用户误认为是全日完整数据。

## 7. 代码输入归一化

### 7.1 规则

港股代码内部统一为 `HK.` 加五位数字。

| 输入 | 归一化结果 |
|---|---|
| `HK.0700` | `HK.00700` |
| `HK.00700` | `HK.00700` |
| `0700` | `HK.00700` |
| `700` | `HK.00700` |
| `hk.700` | `HK.00700` |

### 7.2 校验

- 去除首尾空白并将市场前缀转为大写。
- 第一阶段只允许 `HK` 市场。
- 数字部分必须为 1 至 5 位数字。
- 超过五位、包含字母或包含额外分隔符时返回明确的输入错误。
- 前端和后端都要校验，但后端结果为最终依据。

### 7.3 显示策略

- 输入框保留用户习惯形式 `HK.0700`。
- API 请求和内部日志使用 Futu 标准形式 `HK.00700`。
- 页面证券标题同时显示 `腾讯控股 · HK.00700`，避免歧义。

## 8. Futu OpenD 数据设计

### 8.1 运行前提

- Windows 本机已运行官方 Futu OpenD。
- OpenD 已登录。
- 默认连接 `127.0.0.1:11111`。
- 主机和端口可通过环境变量覆盖。
- 不在仓库内保存 Futu 密码、交易密码或其他凭证。
- OpenD 默认只绑定本机，不开放公网。

环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `FUTU_OPEND_HOST` | `127.0.0.1` | OpenD 地址 |
| `FUTU_OPEND_PORT` | `11111` | OpenD API 端口 |
| `HFQ_HOST` | `127.0.0.1` | Web 服务监听地址 |
| `HFQ_PORT` | `8770` | Web 服务端口 |

### 8.2 Futu 接口映射

| 页面数据 | Futu 接口 | 订阅类型 |
|---|---|---|
| 证券摘要 | `get_market_snapshot` | 无需订阅 |
| 十档盘口 | `get_order_book` | `SubType.ORDER_BOOK` |
| 逐笔成交 | `get_rt_ticker` | `SubType.TICKER` |
| 分时数据 | `get_rt_data` | `SubType.RT_DATA` |
| 日 K | `get_cur_kline` 或历史 K 线接口 | 对应 K 线订阅或历史请求 |
| 市场状态 | `get_market_state` | 无需或按 SDK 要求 |

### 8.3 数据获取策略

后端维护单个行情上下文，避免每次浏览器轮询都新建 OpenD 连接。

加载证券时：

1. 归一化并校验代码。
2. 获取市场快照。
3. 订阅盘口、逐笔和分时。
4. 获取当前盘口。
5. 获取最近逐笔。
6. 获取当日分时。
7. 获取日 K。
8. 将不同接口结果组合为统一响应。

更新频率：

- 快照：3 秒。
- 盘口：1 秒。
- 逐笔：1 秒。
- 分时：15 秒。
- 日 K：60 秒；非交易时段可延长。

浏览器不可无限并发刷新。前一次请求未完成时跳过下一次轮询。

### 8.4 权限与数据限制

Futu 的 LV2 能力取决于账户、市场订阅和当前行情权限。软件必须分别处理：

- OpenD 未启动。
- OpenD 未登录。
- 证券代码不存在。
- 订阅失败。
- 无港股实时行情权限。
- 无十档或逐笔权限。
- 请求频率受限。
- 非交易时段返回上一交易日数据。

页面可部分成功。例如快照可用但逐笔无权限时，仍展示快照，并在逐笔面板显示具体错误。

禁止在失败时生成随机数据、示例数据或“看起来正常”的空壳行情。

## 9. 后端 API 契约

### 9.1 健康检查

`GET /api/health`

返回：

```json
{
  "status": "ok",
  "service": "hfq-lv2-terminal",
  "opend": {
    "connected": true,
    "quote_logged_in": true
  }
}
```

HTTP 服务正常但 OpenD 不可用时，HTTP 状态仍可为 `200`，但 `opend.connected` 必须为 `false` 并包含错误说明。

### 9.2 完整市场数据

`GET /api/market?code=HK.0700`

响应结构：

```json
{
  "code": "HK.00700",
  "requested_code": "HK.0700",
  "name": "腾讯控股",
  "market_time": "2026-09-18 16:08:30",
  "market_state": "CLOSED",
  "snapshot": {},
  "order_book": {
    "bids": [],
    "asks": []
  },
  "tickers": [],
  "intraday": [],
  "daily": [],
  "capabilities": {
    "snapshot": true,
    "order_book": true,
    "ticker": true,
    "intraday": true,
    "daily": true
  },
  "errors": []
}
```

`errors` 为结构化数组，每项至少包含：

- `scope`：失败模块。
- `code`：稳定错误码。
- `message`：适合页面显示的中文信息。

### 9.3 轻量轮询接口

为了降低 OpenD 压力，实时更新拆分为：

- `GET /api/quote?code=HK.0700`
- `GET /api/order-book?code=HK.0700`
- `GET /api/tickers?code=HK.0700&limit=500`
- `GET /api/intraday?code=HK.0700`
- `GET /api/kline?code=HK.0700&period=day&count=120&adjust=forward`

所有接口：

- 返回 JSON。
- 使用 UTF-8。
- 禁止返回 Python 堆栈到浏览器。
- 输入错误返回 `400`。
- OpenD 连接失败返回 `503`。
- Futu 权限错误返回 `403`。
- 未知证券返回 `404`。
- 上游超时返回 `504`。

## 10. 前端状态设计

每个面板独立拥有以下状态：

- `loading`：首次加载骨架。
- `ready`：正常数据显示。
- `empty`：请求成功但无数据。
- `stale`：显示缓存或上一交易日数据。
- `forbidden`：账号无对应行情权限。
- `error`：连接、请求或解析失败。

全局状态不得覆盖局部状态。例如盘口无权限时，分时和日 K 仍可工作。

状态文案示例：

- `Futu OpenD 已连接`
- `行情日期：2026-09-18，当前为非交易时段`
- `当前账号没有港股十档盘口权限`
- `无法连接 Futu OpenD，请确认 127.0.0.1:11111 已启动并登录`
- `HK.0700 已归一化为 HK.00700`

### 11.2 密度与尺寸

- 目标分辨率：`1440 × 900` 及以上。
- 最低可用宽度：`1180px`。
- 表格行高：28 至 32px。
- 数字使用等宽字体。
- 价格统一保留证券对应精度。
- 大数字使用万、亿缩写，同时通过悬停显示原值。
- 关键状态不可只依赖红绿颜色，需配合文字、图标或方向标签。

### 11.3 响应式策略

- 宽度大于 `1400px`：三栏完整布局。
- `1180px` 至 `1399px`：缩窄自选和盘口栏。
- 小于 `1180px`：盘口移到主图下方；不以横向溢出作为主要方案。

## 12. 性能与可靠性

- 页面首次可交互目标：本机 2 秒内，不含 OpenD 首次响应。
- 单次实时轮询超时：5 秒。
- 历史 K 线请求超时：15 秒。
- 后端缓存快照 1 秒、分时 10 秒、日 K 60 秒。
- 逐笔数据按时间和成交标识去重。
- 内存中每只证券最多保留 1000 笔逐笔。
- 浏览器表格默认只渲染 500 行。
- 用户切换证券时取消或忽略旧证券的未完成请求。
- 服务关闭时主动取消订阅并关闭 Futu 上下文。

## 13. 安全设计

- Web 服务默认只监听 `127.0.0.1`。
- 不提供任意代理接口。
- 不接受任意文件路径。
- 证券代码经白名单格式校验后才传给 Futu SDK。
- 错误响应不泄露本机目录、环境变量或调用栈。
- CSV 导出在浏览器本地完成，不写入服务器任意路径。
- 不记录账号凭证或完整交易账户信息。

## 15. 测试策略

### 15.1 单元测试

- 港股代码归一化。
- 非法代码拒绝。
- Futu DataFrame 和盘口元组到 API 模型的转换。
- 逐笔方向映射。
- 汇总统计。
- 结构化错误映射。

### 15.2 API 集成测试

使用伪造的 Futu 客户端，不访问真实 OpenD，验证：

- 健康检查。
- 完整市场响应结构。
- 各轻量接口。
- 部分模块失败时的降级。
- HTTP 状态码。
- 静态文件服务。

### 15.3 `HK.0700` 实盘数据测试

真实测试必须连接本机 Futu OpenD，并使用用户输入 `HK.0700`：

1. 验证内部归一化为 `HK.00700`。
2. 验证证券名称为腾讯控股。
3. 验证快照包含有效最新价、昨收、成交量或成交额。
