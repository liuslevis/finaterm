# AMBUSH：底部异常订单流识别策略

> 状态：研究与实现规格  
> 数据范围：沪深 A 股日线、证券主数据、Level-2 逐笔委托、逐笔成交、十档行情快照  
> 现有原型：`predictor\ambush\strategy.py`  
> 目标：将“底部僵化股票突然启动、启动前存在大量稳定卖单”的市场叙事，转化为可复现、可回测、无未来函数的研究策略

## 1. 结论与原则

这套方法可以实现，但必须拆成三个可验证的问题：

1. **标的是否处于低活跃底部**：只用信号日前的日线、成交量和换手率判断。
2. **当日是否发生有效启动**：用价格、量能和主动买入识别启动起点 `t_start`，并记录实时可确认时刻 `t_detect`。
3. **启动前卖单是否集中、持续且低撤单**：按委托号重建订单生命周期，估算挂单暴露，而不是推断账户身份。

逐笔数据没有账户、席位或投资者身份，因此不能证明：

- 多笔委托属于同一个“主力”；
- 某笔卖单代表主力持仓；
- 买卖双方属于同一账户；
- “自己挂自己吃”、护盘或操纵行为真实发生。

系统事实层只能使用“卖单暴露”“持续订单”“撤单”“成交吸收”“补单”等可验证术语，输出应命名为**控盘代理信号**或**异常订单流信号**，不得输出“已确认主力控盘”。

视频中的“启动前卖单总量 / 流通股本 ≥ 10%”只是宽松上界。总卖单会受到撤单、重复挂撤、成交后重新挂出和普通投资者挂单污染，`10%` 不能单独作为买入条件。

现有原型的短期研究结果表明：

- “底部僵化 + 首次有效启动”具有进一步研究价值；
- “卖单越多、主动买入越强越好”的 LV2 排序在样本外不稳定，部分因子方向甚至相反；
- 过大的卖单、撤单、主动买入 Delta 和大单净流入可能代表拥挤或派发；
- LV2 因子现阶段只适合用于候选内确认、解释和排除，不应直接推导仓位。

## 2. 目标与非目标

### 2.1 目标

- 每个交易日从全市场生成底部僵化池；
- 盘中或收盘后识别首次有效启动；
- 精确重建启动前订单的新增、成交、撤单和剩余量；
- 输出可解释的证据链、置信等级、数据质量和失效原因；
- 支持逐笔复盘、事件回测和参数版本管理；
- 严格保证任一时刻的信号只使用当时已经可见的数据。

### 2.2 非目标

- 不识别真实账户、营业部或资金主体；
- 不把总挂单量直接当作实际持仓；
- 不把疑似对倒、护盘或操纵描述成事实；
- 不因“大资金成本更高”而取消止损；
- 第一阶段不自动下单，只生成研究信号和复盘材料。

## 3. 数据输入与规范化

### 3.1 原始归档

Level-2 归档格式：

```text
hfq\data-lv2\YYYYMMDD.7z
└── YYYYMMDD\<code>.SZ|.SH\
    ├── 行情.csv
    ├── 逐笔委托.csv
    └── 逐笔成交.csv
```

CSV 使用 GBK 编码。应先读取 7z 文件索引确定当日可用证券，只解压命中候选的三个 CSV，禁止每天解压全市场全部逐笔数据。

### 3.2 必需数据

| 数据 | 必需字段 | 用途 |
|---|---|---|
| 日 K | 日期、前复权 OHLC、成交量、成交额、换手率 | 底部筛选、事件收益 |
| 证券主数据 | 代码、名称、板块、上市日期、ST 状态、流通股本 | 涨跌停规则、排除项、比例计算 |
| 逐笔委托 | 时间、交易所序号、方向、价格、数量、操作类型 | 订单创建与撤单 |
| 逐笔成交 | 时间、成交序号、价格、数量、BS 标志、买卖委托号、成交代码 | 成交归因、订单消耗、深市撤单 |
| 十档快照 | 时间、最新价、累计成交、买卖十档价量 | 启动识别、盘口失衡、结果校验 |

现有 Wind CSV 的关键列：

| 文件 | 用途 | 关键列 |
|---|---|---|
| `逐笔委托.csv` | 新增委托，沪市还包含撤单 | `[3]` time、`[5]` seq、`[6]` type (`A/D`)、`[7]` side、`[8]` price、`[9]` qty |
| `逐笔成交.csv` | 成交，深市还包含撤单 | `[3]` time、`[5]` code (`C` 为撤单)、`[7]` aggressor、`[8]` price、`[9]` qty、`[10]` sellSeq、`[11]` buySeq |
| `行情.csv` | 十档快照 | `[4]` last、`[27..36]` 卖十档量、`[47..56]` 买十档量 |

列位置必须封装为具名 schema，不能让魔法下标散落在业务模块中。价格原值为“元 × 10000”，解析后立即统一：

```text
price : Decimal yuan
qty   : int shares
time  : int HHMMSSmmm
seq   : int
side  : B | S
event : ADD | FILL | CANCEL
```

金额和比例计算优先使用 `Decimal` 或整数价格单位，避免浮点误差影响涨停价和订单聚合。

### 3.3 沪深市场差异

- **深交所**：新增来自 `逐笔委托.csv`；撤单通常是 `逐笔成交.csv` 中 `code == 'C'` 的记录，通过 `buySeq` 或 `sellSeq` 关联原委托。
- **上交所**：新增和撤单都在 `逐笔委托.csv`，通过 `type == 'A'/'D'` 区分；成交文件用于扣减订单剩余量。
- 所有事件按交易所序号排序，时间仅用于展示和区间查询。同毫秒必须由序号决定先后。
- 若不同来源序号不处于同一序列空间，解析层必须先明确交易所语义并形成确定的事件合并规则，不得仅按时间任意排序。

### 3.4 时点主数据

流通股本、ST 状态和涨跌停规则必须使用信号日当时可知的 point-in-time 值，并按公告生效日、送转、增发和限售股解禁维护版本。

若流通股本缺失或非正数：

- 仍可计算绝对订单流指标；
- 所有占流通股比例字段返回空值；
- 信号必须降级，不得产生 `high`；
- 不得用总股本或当前最新流通股本静默替代。

## 4. 总体架构

```text
全市场
  └─ 阶段一：T-1 日线与时点主数据
       └─ 底部僵化池
            └─ 阶段二：T 日启动检测
                 └─ 仅加载命中标的 LV2
                      └─ 委托生命周期与委托地图
                           └─ 三层卖单暴露与订单流因子
                                └─ 分级、评分、回踩确认
                                     └─ 事件回测与逐笔复盘
```

两阶段架构用于控制成本：

1. 全市场日线预筛只读取低频数据；
2. 只对“底部池 ∩ 当日启动”的少量股票解压和回放 Level-2。

## 5. 阶段一：底部僵化池

所有指标只使用信号日 `T` 之前的数据，最后一根可用 K 线必须为 `T-1` 或更早。

### 5.1 硬过滤

- A 股普通股票，排除 ST、退市整理、停牌和上市不足 120 个交易日的标的；
- 最近 20 日有效交易日不少于 18 日；
- 最近 20 日平均成交额默认不低于 2000 万元；
- 近 20 日触及涨停次数不超过 1 次，避免捕获已反复启动的股票。

### 5.2 底部指标

| 指标 | 公式 | 默认门槛 |
|---|---|---:|
| 240 日价格位置 | `(close[T-1] - low_240) / (high_240 - low_240)` | `≤ 40%` |
| 60 日区间振幅 | `high_60 / low_60 - 1` | `≤ 40%` |
| 20 日平均绝对收益 | `mean(abs(close.pct_change()))` | `≤ 2.5%` |
| 20 日平均换手率 | `mean(turnover_20)` | `≤ 2.5%` |
| 近期缩量比 | `mean(volume_20) / median(volume_120)` | 优先 `< 0.8` |
| 20 日最大单日涨幅 | `max(return_20)` | `< 5%` |

“日均涨幅不超过 5%”不能使用有正有负的平均收益，否则涨跌会互相抵消。必须分别保留：

- `mean_abs_return_20d_pct`：衡量股性僵化；
- `max_positive_return_20d_pct`：排除近期已活跃股票。

### 5.3 躺平分

```text
dormancy_score =
    30% * low_price_position_rank
  + 20% * low_60d_range_rank
  + 20% * low_abs_return_rank
  + 15% * low_turnover_rank
  + 15% * low_recent_volume_rank
```

硬门槛用于保证语义，分数只用于同一信号日的候选排序。低值更好的指标应先反向转为百分位，禁止跨日期直接比较原始量级。

## 6. 阶段二：动态启动检测

视频案例使用固定 `13:20`，但生产系统必须动态识别，并严格区分：

- `t_start`：价格和成交量开始突变的分钟起点，用作启动前订单统计截止点；
- `t_detect`：首个完整滚动窗口满足全部条件的结束时刻，也是实时系统最早可发出信号的时刻。

**启动前因子只能读取 `≤ t_start` 的事件，任何模拟成交不得早于 `t_detect`。**

### 6.1 启动条件

按 1 分钟聚合逐笔成交或快照，某窗口同时满足：

- 从昨收到当前的涨幅达到所属板块涨停幅度的 70%，或 3 分钟收益不低于 3%；
- 最近 3 分钟成交量不低于此前 20 个有效分钟中位数的 8 倍；
- 最近 3 分钟主动买入量占比不低于 60%；
- 最近 3 分钟成交量不低于窗口开始前当日累计成交量的 10%；
- 价格创当日新高。

若数据不足 20 个有效分钟，应明确采用预热状态或版本化替代基线，不能用不足窗口与完整窗口混算。

涨停幅度和涨停价由证券主数据按日期提供，并遵循交易所最小价格单位和舍入规则。不能仅按证券代码永久硬编码主板 10%、双创 20% 或 ST 5%。

`09:25` 集合竞价附近的启动单独标记为 `AUCTION_TRIGGER`，不得与连续竞价三分钟窗口混算。只有日线时可用“触达涨停价”生成离线候选，但加载 LV2 后必须补算 `t_start` 和 `t_detect`。

### 6.2 启动质量

```text
trigger_score =
    35% * event_volume_ratio_rank
  + 25% * max_3m_aggressive_buy_ratio_rank
  + 20% * price_acceleration_rank
  + 20% * low_pre_event_turnover_rank
```

启动质量描述事件强度，不构成主力证据。

## 7. 委托生命周期与委托地图

### 7.1 生命周期状态

```python
OrderState = {
    "order_id": int,
    "side": "B" | "S",
    "price": Decimal,
    "created_at": int,
    "original_qty": int,
    "filled_qty": int,
    "canceled_qty": int,
    "remaining_qty": int,
    "last_event_at": int,
    "status": "OPEN" | "PARTIAL" | "FILLED" | "CANCELED",
}
```

按确定的事件顺序回放：

- `ADD`：创建订单；
- `FILL`：通过买卖委托号分别扣减对应订单；
- `CANCEL`：扣减撤单数量；
- `remaining_qty = original_qty - filled_qty - canceled_qty`。

负剩余量、孤立撤单、未知委托号和重复订单号必须记录为数据质量错误，不得通过 `max(..., 0)` 静默掩盖；对外结果可截断展示，但原始异常必须保留并参与降级。

### 7.2 “挂单不动”的计算含义

订单本身不会在价格间移动，改价等于撤旧单并挂新单。因此委托地图中的“稳定卖墙”应定义为：

1. 同一价格带持续存在大量剩余卖量；
2. 组成价格带的订单寿命较长；
3. 旧单成交或撤销后，同价在短时间内出现补单；
4. 价格带长期位于当时市场价格上方。

委托地图是证据展示界面，不是账户关系图。任何颜色、标签和提示都必须对应可复算字段。

### 7.3 截止时刻

所有启动前指标截止于动态 `t_start`，计算结果在 `t_detect` 后才可用。固定 `13:20:00.000` 口径可以保留为研究对照字段，但不能参与实时信号，也不能用于早于 13:20 启动的样本。

## 8. 三层卖单暴露

设信号日时点流通股本为 `F`。

### 8.1 总卖单暴露上界

```text
gross_sell_qty =
    Σ original_qty(sell orders created_at ≤ t_start)

gross_sell_float_ratio = gross_sell_qty / F
```

这是最接近视频口径、也最容易被重复挂撤放大的宽松上界。

### 8.2 截点有效卖单

```text
active_sell_qty =
    Σ remaining_qty@t_start(sell orders created_at ≤ t_start)

active_sell_float_ratio = active_sell_qty / F
```

它排除了 `t_start` 前已经成交或撤销的数量，更适合描述启动前仍暴露的卖压。

### 8.3 持续固定卖单

```text
persistent_sell_qty =
    Σ remaining_qty@t_start
      where side = S
        and original_qty ≥ 10,000
        and lifetime_at_t_start ≥ 30 minutes

persistent_sell_float_ratio = persistent_sell_qty / F
persistent_sell_share = persistent_sell_qty / gross_sell_qty
```

大额和长寿命阈值是初始研究参数，必须版本化。`persistent_sell_share` 只是“稳定卖墙”的代理，不能证明订单归属。

`10%` 门槛只能应用于 `gross_sell_float_ratio`，字段名为 `gross_proxy_pass`。界面必须同时展示 `gross / active / persistent`，禁止汇总成单一“主力持仓”数字。

## 9. Level-2 因子

### 9.1 挂单真实性

| 字段 | 定义 | 解释 |
|---|---|---|
| `sell_fill_ratio` | `t_start` 前卖单成交量 / 总卖单量 | 卖单是否被实际消化 |
| `sell_cancel_ratio` | `t_start` 前卖单撤单量 / 总卖单量 | 过高可能是展示性挂单 |
| `persistent_sell_share` | 持续卖单 / 总卖单量 | 卖墙是否长期存在 |
| `active_to_gross_ratio` | 截点有效卖单 / 总卖单量 | 排除重复挂撤后的膨胀 |
| `sell_refill_float_ratio` | 同价订单耗尽后 3 秒内新增卖量 / `F` | 卖墙是否持续补充 |

所有分母为零的比例必须返回空值或定义明确的状态，不得静默返回零。

### 9.2 启动吸收

- `max_aggressive_buy_3m`：任意连续 180 秒主动买成交量峰值；
- `launch_absorption_ratio`：`[t_start, t_detect]` 主动买入量 / `t_start` 前有效卖单量；
- `launch_price_efficiency`：三分钟价格涨幅 / 三分钟成交量占流通股比例；
- `time_to_limit_seconds`：从 `t_start` 到首次触及涨停的秒数；
- `limit_seal_ratio`：首次封板后封单量 / `F`；
- `open_board_count`：首次封板后的开板次数。

“三分钟成交两亿”等绝对量必须同时相对流通股本、事件日成交量和启动前有效卖量归一化，不能跨股票直接比较。

### 9.3 成交与盘口

- `delta_ratio = (aggressive_buy_qty - aggressive_sell_qty) / trade_qty`；
- `large_order_net_flow_ratio`：以当日成交量 95 分位数定义大单并计算主动净流；
- `stacked_buy_imbalance_levels`：买方成交量至少为卖方三倍的最长连续相邻价位数；
- `low_band_sell_absorption_ratio`：当日价格区间底部 20% 中主动卖出量 / 全日主动卖出量；
- `buy_refill_float_ratio`：同价买单耗尽后 3 秒内新增买量 / `F`；
- `median_order_book_imbalance`：十档 `(BidQty - AskQty) / (BidQty + AskQty)` 中位数；
- `post_launch_churn_ratio`：启动后三分钟成交量 / 同期价格净位移。

主动买卖方向依赖成交数据的 BS 标志。若缺失，不得用价格涨跌机械替代；相关因子置空并降低置信度。

### 9.4 高频换手代理

没有账户标识时只能输出 `churn_proxy`，可由以下证据组成：

- 窄价带内成交量极大但净价格位移很小；
- 买卖两侧在秒级同时快速补单；
- 大量订单短寿命且成交后迅速在同价补回；
- 成交 Delta 很大，但盘口净变化和价格响应较弱。

界面文案只能写“疑似对敲式换手代理”或“高频换手代理”，不得写“主力自买自卖”。

## 10. 信号状态、分级与评分

### 10.1 状态机

```text
DORMANT
  -> TRIGGERED
  -> CONTROL_CANDIDATE
  -> RETEST_READY
  -> ENTERED
  -> INVALID
```

状态变更必须记录时间、规则版本和逐条原因。

### 10.2 规则分级

| 等级 | 条件 |
|---|---|
| `watch` | 通过底部筛选并发生有效启动 |
| `medium` | `gross_sell_float_ratio ≥ 5%` 或 `persistent_sell_share ≥ 5%`，且数据完整 |
| `high` | `gross_sell_float_ratio ≥ 10%`、`active_sell_float_ratio ≥ 2%`、`persistent_sell_share ≥ 5%`、`sell_cancel_ratio ≤ 50%` 同时成立 |
| `invalid` | 数据不完整、流通股本失真、启动失败、巨量冲高回落或硬风险触发 |

以上阈值只是研究起点，必须在滚动样本外验证后调整。

### 10.3 评分

```text
total_score =
    45% * dormancy_score
  + 20% * trigger_score
  + 35% * lv2_confirmation_score
```

三个子分必须分别保留，不能只输出黑盒总分。LV2 原始值先转为同一信号日候选横截面百分位；实时模式只能使用当前时刻已检测到的候选，不能提前使用收盘后的完整候选集合。

LV2 因子方向和权重必须从版本化模型配置加载，不能写死“越大越好”。模型配置至少包含：

- 版本号；
- 训练起止日期、样本量和交易日数；
- 字段方向与权重；
- 训练数据截止日期；
- 样本外评估结果。

## 11. 交易执行与风险控制

### 11.1 可执行时点

- 收盘后归档数据最早只能在 `T+1` 交易；
- 实时流版本最早成交时间也必须晚于 `t_detect`；
- 禁止用启动前价、`t_start` 价格或不可成交的涨停价回填成交。

默认执行为启动后的回踩确认，而不是追涨停瞬间：

- `T+1` 至 `T+5` 内出现回踩；
- 收盘仍位于启动前箱体上沿或启动日 VWAP 之上；
- 回踩日成交量低于启动日的 50%；
- 未跌破启动日最低价；
- 回踩期间没有持续显著主动卖出或卖墙异常撤单；
- 次日高开超过 7% 时不追入。

入场价使用次日开盘、VWAP 或规则触发后的下一根 bar，并计入滑点、冲击成本和涨跌停不可成交约束。

### 11.2 退出

- 硬止损：跌破启动日最低价或入场价 `-8%`，取先触发者；
- 结构止损：回到启动前箱体且连续两日无法收复；
- 止盈：盈利 `+15%` 后移动止盈，或 `+25%` 分批退出；
- 时间止损：入场后 10 个交易日未创新高；
- 最长持有：15 个交易日。

退出规则必须分别回测，不得因推定“大资金成本在底部”而取消止损。

### 11.3 仓位

- 单票风险预算不超过组合净值的 0.5%；
- 单票仓位上限默认 5%；
- 同行业信号合计上限 20%；
- 一字板、无合理成交量或预估冲击成本过高时跳过；
- `high` 只决定是否进入候选，不直接线性放大仓位。

## 12. 回测设计

### 12.1 防未来函数

- 底部池只使用 `T-1` 及以前的数据；
- 启动前订单因子只读取 `≤ t_start` 的事件；
- 启动窗口因子只读取 `≤ t_detect` 的事件；
- 任何模拟成交不得早于 `t_detect`；
- 流通股本和证券状态按公告生效日查询；
- 保留退市、历史 ST、停牌和曾上市标的，避免幸存者偏差；
- 前复权价格用于收益连续性，真实未复权价格用于成交、订单和涨跌停判断；
- 实时横截面排名不得提前知道收盘后的完整候选集合。

### 12.2 样本划分

采用按日期滚动的 walk-forward：

1. 至少收集 6 个月并覆盖不同市场环境；
2. 前 3 个月用于选择因子方向和阈值；
3. 后续每个月只用此前数据训练，在下个月完全样本外验证；
4. 参数最多每月更新一次，并保存模型版本；
5. 同一股票不同日期的事件不得随机拆到训练集和测试集两侧。

现有少量样本只能作为原型验证，不能支持稳定实盘结论。

### 12.3 对照组

必须同时报告：

- 全部底部僵化股；
- 底部僵化但未启动；
- 非底部但触达涨停；
- 底部启动但未通过 LV2；
- 底部启动且通过 LV2；
- 按行业、市值和当日涨幅匹配的对照组。

筛选能力和排序能力必须分开评估：

1. **筛选能力**：底部启动相对各对照组是否有增量收益；
2. **排序能力**：分数的 Spearman 相关和高中低分组收益是否单调。

### 12.4 指标

- 3、5、10、15 个交易日收益和相对基准超额收益；
- 胜率、平均值、中位数、盈亏比；
- MFE、MAE、最大回撤和收益波动；
- Spearman 排序相关及分组单调性；
- 95% Wilson 胜率区间；
- bootstrap 收益置信区间；
- 按日期聚类的显著性检验；
- 扣除佣金、印花税、滑点和不可成交约束后的结果。

若高分组不能稳定优于低分组，分数只能用于解释，不能用于仓位排序。

## 13. 数据质量与降级

每只股票每天生成质量报告：

- 委托号唯一性和重复数；
- 成交关联到未知委托号的数量与成交量比例；
- 撤单关联失败比例；
- 负剩余量数量；
- 行情快照最大间隔；
- 逐笔累计成交量与行情累计成交量偏差；
- 价格单位、时间范围和事件序号单调性；
- 流通股本的日期、来源和版本；
- `t_start` 前数据覆盖范围。

默认硬性降级条件：

- 未知订单关联量超过全日成交量 1%；
- 快照中断超过 60 秒；
- 逐笔成交量与行情累计成交量偏差超过 1%；
- 流通股本缺失或非正数；
- `t_start` 前 30 分钟数据不完整；
- 主动买卖方向缺失但规则依赖相关因子。

降级时保留复盘数据和明确原因，但不得产生 `high` 信号。所有阈值均应配置化和版本化。

## 14. 软件落地

### 14.1 模块结构

```text
hfq\
├── app\
│   ├── data.py
│   └── ambush\
│       ├── schema.py
│       ├── universe.py
│       ├── dormant.py
│       ├── trigger.py
│       ├── lifecycle.py
│       ├── factors.py
│       ├── scoring.py
│       ├── scan.py
│       └── backtest.py
├── cache\ambush\
│   ├── kline\
│   ├── fundamentals\
│   ├── factors\
│   └── models\
└── design\AMBUSH.md
```

职责：

- `schema.py`：规范字段、沪深原始列定义和类型；
- `universe.py`：证券池、时点主数据和流通股本；
- `dormant.py`：`T-1` 底部池；
- `trigger.py`：动态 `t_start / t_detect`；
- `lifecycle.py`：沪深订单生命周期重建；
- `factors.py`：三层卖单暴露和订单流因子；
- `scoring.py`：规则分级和版本化模型；
- `scan.py`：每日批处理；
- `backtest.py`：事件回测，分别评估筛选与排序。

现有 `predictor\ambush\strategy.py` 作为算法原型保留，正式实现应逐步抽取模块，不能继续把选池、下载、回放、评分和评估堆在一个文件中。

### 14.2 批处理与产物

```powershell
python -m hfq.app.ambush.scan --date 20260918
python -m hfq.app.ambush.backtest --start 20260101 --end 20260918
```

输出：

```text
ambush_pool_<date>.parquet
ambush_triggers_<date>.parquet
ambush_factors_<date>.parquet
ambush_signals_<date>.csv
ambush_evaluation_<run_id>.json
```

CSV 用于人工查看，Parquet 保存全精度中间结果。每份结果附带 `data_version`、`factor_version`、`model_version` 和生成时间。

- `gross / active / persistent` 三张证据卡；

禁止只显示一个“主力持仓”数字，禁止使用账户级确定性文案。

## 15. 测试与验收

### 15.1 单元测试

- 深市新增、部分成交、完整成交和撤单生命周期；
- 沪市 `A / D` 生命周期；
- 同毫秒不同序号的稳定排序；
- 午间休市、集合竞价、涨停价和最小价格单位；
- `t_start` 指标不读取启动后事件；
- `t_detect` 只读取已经结束的启动窗口；
- `gross / active / persistent` 公式；
- 分母为零和流通股本缺失时的空值与降级；
- 同价 3 秒补单的时间边界；
- 未知委托、重复委托和负剩余量的质量报告。

### 15.2 数据回放测试

至少覆盖：

- 启动前稳定卖墙、三分钟拉升；
- 大量挂单随后撤掉的展示型案例；
- 正常活跃股的自然大量委托；
- 一字涨停；
- 集合竞价启动；
- 冲板后快速炸板；
- 无 BS 标志或快照缺口的降级案例。

逐笔回放到 `t_start` 的结果必须与截断原文件到 `t_start` 后离线重算逐股一致；回放到 `t_detect` 的触发结果必须与截断到 `t_detect` 后重算一致。

### 15.3 第一阶段验收

- 无需解压全市场全部逐笔文件即可生成候选；
- 每个候选都能展示 `t_start`、`t_detect` 和原始启动窗口；
- 任意订单可追踪新增、成交、撤单和剩余量；
- 三层卖单暴露可从原始记录复算；
- 信号包含等级、原因、数据质量和模型版本；
- 回测明确区分筛选与排序，并计入成本和不可成交约束；
- 页面和导出均不把代理指标描述为真实主力持仓。

## 16. 最小可行实现顺序

1. **优先实现 `schema.py`、`lifecycle.py` 和单元测试**：打通沪深两套生命周期、同毫秒排序和剩余量恒等式。
2. 用截断文件重算验证逐笔回放结果，确保生命周期是可信地基。
3. 将固定 `13:20` 替换为动态 `t_start / t_detect`，固定口径仅保留为研究对照。
4. 实现三层卖单暴露和每日数据质量报告。
5. 接入 point-in-time 流通股本、ST 状态和按日期涨跌停规则。
6. 在委托地图增加时间线、三态卖单和证据卡。
7. 建立多月 walk-forward，在冻结样本外月份分别验收筛选和排序。
8. 只有不同市场阶段均稳定提升后才进入模拟盘；模拟盘通过后再讨论自动执行。

## 17. 风险声明

本策略研究公开行情中的订单流形态，不识别真实交易主体。挂单可以撤销，逐笔委托可以重复，历史表现可能来自涨停效应、低位反转或小市值风格暴露。任何“主力”“控盘”“护盘”“对倒”都只能作为便于理解的市场叙事，系统事实层必须使用可验证术语。

本设计不构成投资建议。
