# AMBUSH_OPUS：用逐笔委托实现「底部主力进场识别」的落地方案

> 状态：实现方案（工程视角）
> 配套文档：`AMBUSH.md`（研究规格）、`predictor\ambush\strategy.py`（现有原型）
> 目标：把视频里「委托地图 → 判断主力控盘 → 底部跟随」的直觉，落成一条**只用已有 Level-2 逐笔数据、无未来函数、可复算**的流水线。

本文只回答一个问题：**手上有逐笔委托 / 逐笔成交 / 十档快照，这套策略具体怎么写。**
概念、非目标、免责声明见 `AMBUSH.md`，此处不重复。核心立场先说清楚：

- 逐笔数据**没有账户身份**。所有「主力」「控盘」「护盘」「自买自吃」都是**叙事**，代码里只允许出现「卖单暴露 / 持续订单 / 撤单 / 成交吸收 / 补单」这类可验证词。
- 视频的「1.76 亿卖单 = 主力持仓」是**上界**，不是持仓。它会被撤单、重复挂撤、成交后再挂、普通投资者挂单污染。
- 现有原型已证明：**「躺平 + 首涨停」筛选在 3D/1W 有价值，但「卖单越多越强」的 LV2 排序在样本外反向**。所以 `10%` 只能当宽松代理，不能当买入触发。

## 0. 手上数据的真实形态（实现从这里开始）

归档：`hfq\data-lv2\YYYYMMDD.7z`，内部结构 `YYYYMMDD/<code>.SZ|.SH/{行情,逐笔委托,逐笔成交}.csv`，**GBK 编码**。

统一解析后的规范字段（解析后立刻转成这些，后续模块不再碰原始列）：

```text
price : Decimal 元        # 原始为「元 × 10000」，除以 PRICE_SCALE=10000
qty   : int 股
time  : int HHMMSSmmm      # 交易所本地时钟，毫秒精度，仅用于展示/区间查询
seq   : int               # 交易所序号，同毫秒事件唯一按它排序
side  : 'B' | 'S'
event : 'ADD' | 'FILL' | 'CANCEL'
```

关键列位置（来自现有 `analyze_lv2`，实现时用具名 schema 固化，别散在魔法下标里）：

| 文件 | 用途 | 关键列 |
|---|---|---|
| `逐笔委托.csv` | 新增委托（SH 还含撤单 `D`） | [3]time [5]seq [6]type(A/D) [7]side [8]price×1e4 [9]qty |
| `逐笔成交.csv` | 成交 + SZ 撤单 | [3]time [5]code(`C`=撤) [7]aggressor(B/S) [8]price [9]qty [10]sellSeq [11]buySeq |
| `行情.csv` | 十档快照 | [4]last×1e4；卖十档量 [27..36]；买十档量 [47..56] |

**沪深差异是本策略最大的实现坑，必须显式分支：**

- **深交所（.SZ）**：新增来自 `逐笔委托`；撤单在 `逐笔成交` 里 `code=='C'`，用 `buySeq or sellSeq` 关联回原委托。
- **上交所（.SH）**：新增和撤单**都在** `逐笔委托`，`type=='A'` 新增、`type=='D'` 撤单；成交文件只用于扣减剩余量。
- 所有事件按 `seq` 排序，**时间只做展示**。同毫秒必须用 `seq` 决胜，否则生命周期会算错。

## 1. 架构：两阶段，别每天解压全市场

```text
全市场
  └─[阶段一] 只读日线/流通股本 → T-1 底部僵化池        (便宜，全市场)
        └─[阶段二] 池内 ∩ 当日启动 → 只对这几十只解压 LV2   (贵，极少量)
              └─ 委托地图重建 → 三层卖单暴露 + 订单流因子 → 分级/评分
                    └─ T+1 回踩确认 → 事件回测
```

理由：一天全市场逐笔是几 GB，`7z` 索引可先只读**文件名**确定当日哪些股有 LV2，再只解压命中标的的 3 个 csv。现有原型已经这么做（`extract_members` 只取命中 code 的成员），沿用。

## 2. 阶段一：底部僵化池（只用 T-1 及更早）

把视频的「长期底部、股性僵化、量能极低、没被反复炒过」翻成硬门槛 + 排序分。默认阈值直接复用 `AMBUSH.md §5`：

| 指标 | 公式 | 门槛 |
|---|---|---:|
| 240 日价格位置 | `(close[T-1]-low240)/(high240-low240)` | ≤ 40% |
| 60 日振幅 | `high60/low60 - 1` | ≤ 40% |
| 20 日平均**绝对**日收益 | `mean(abs(pct_change))` | ≤ 2.5% |
| 20 日平均换手 | `mean(turnover)` | ≤ 2.5% |
| 20 日最大单日涨幅 | `max(return_20)` | < 5% |

**实现要点**（血泪教训）：

- 「日均涨幅 ≤ 5%」**不能**用有正负的平均收益（会抵消）。必须拆成 `mean_abs_return`（衡量僵化）+ `max_positive_return`（排除近期已活跃）。
- 硬门槛保证语义；`dormancy_score` 只做**同一信号日横截面**百分位排序，禁止跨日比较原始量级。
- 排除 ST / 退市 / 停牌 / 上市 < 120 交易日；近 20 日已触涨停 > 1 次的剔除（避免抓到已经启动的）。
- 平均成交额 `≥ 2000 万`，否则买了出不来。

## 3. 阶段二·启动检测：动态 `t_start` / `t_detect`（这是无未来函数的命门）

视频用固定 `13:20`——那是**事后**看着图说的。生产必须动态检测，且严格区分两个时刻：

- `t_start`：价量突变的**起点**分钟 → 用作「启动前订单」统计截止点。
- `t_detect`：滚动窗口**首次**确认全部启动条件的结束时刻 → **实时最早能发信号、最早能成交**的时刻。

回测/实盘铁律：**启动前因子只读 ≤ `t_start` 的事件；任何模拟成交不得早于 `t_detect`。**

启动条件（1 分钟聚合，同时满足记为候选起点，参 `AMBUSH.md §6.1`）：

```text
涨幅达板块涨停幅度 70%  或  3 分钟收益 ≥ 3%
且 近 3 分钟量 ≥ 前 20 有效分钟中位数 × 8
且 近 3 分钟主动买占比 ≥ 60%
且 近 3 分钟量 ≥ 当前累计量 × 10%
且 价格创当日新高
```

涨停幅度按证券主数据**按日期**给（主板 10% / 双创 20% / ST 5%），别用代码永久硬编码。
`09:25` 集合竞价附近的启动单独标 `AUCTION_TRIGGER`，不与连续竞价三分钟混算。

> 现有原型用「触达涨停价」作离线代理是可以的，但加载 LV2 后**必须补算** `t_start`/`t_detect`，否则固定 13:20 会污染早于 13:20 启动的样本。

## 4. 委托地图重建：把「挂单几乎不动」变成可计算量

视频靠肉眼拖时间轴看「上方卖单一大片、几乎不动」。算法里**订单不会移动**——改价 = 撤旧单 + 挂新单。所以「不动的卖墙」要重述为四个可算特征：

1. 同一价格带**持续存在**大量剩余卖量；
2. 组成该带的订单**寿命长**；
3. 旧单被吃/撤后，同价**短时间内被新单补回**（冰山/补墙）；
4. 该价格带长期处于当时市价**上方**。

### 4.1 订单生命周期状态机

```python
OrderState = {
  "seq": int, "side": 'B'|'S', "price": Decimal, "created_at": int,
  "original_qty": int, "filled_qty": int, "canceled_qty": int,
  "remaining_qty": int,      # = max(original-filled-canceled, 0)
  "last_event_at": int, "status": 'OPEN'|'PARTIAL'|'FILLED'|'CANCELED',
}
```

按 `seq` 顺序回放：ADD 建单；FILL 累加 `filled_qty`（成交文件按 buySeq/sellSeq 双边归因）；CANCEL 累加 `canceled_qty`（SZ 来自成交 `C`，SH 来自委托 `D`）。

**数据质量硬校验**（出现即记错误、不静默修补）：`remaining < 0`、孤立撤单、关联到不存在的 seq。未知关联量 > 全日成交 1% 时降级，不出 `high`。

### 4.2 三层卖单暴露（核心，替代「1.76 亿 = 持仓」）

设流通股本 `F`，截止 `t_start`：

```text
# ① 上界（最接近视频口径，最容易被重复挂撤灌水）
gross_sell   = Σ original_qty(卖单, created_at ≤ t_start)
gross_ratio  = gross_sell / F

# ② 截点仍暴露的有效卖压（剔除已成交/已撤）
active_sell  = Σ remaining_qty@t_start(卖单)
active_ratio = active_sell / F

# ③ 「剧本单」可计算代理：大额 + 长寿命 + 仍未消耗
persistent_sell   = Σ remaining_qty@t_start
                    where original_qty ≥ 1e4 and lifetime@t_start ≥ 30min
persistent_share  = persistent_sell / gross_sell
```

`10%` 门槛**只能**贴给 `gross_ratio`，标 `gross_proxy_pass`。高置信必须同时要求 `active` + `persistent` + 低撤单支撑——现有原型正是这么分的 `gross/active/persistent` 三字段，界面禁止只显示一个「主力持仓」数字。

## 5. 订单流因子：逐条对应视频说法（做好引用，别过度解读）

| 视频说法 | 可计算因子 | 定义 |
|---|---|---|
| 挂单不动、是剧本单 | `persistent_sell_share` / `sell_cancel_ratio` | 持续卖单占比 / 撤单占比（过高=展示性挂单） |
| 主力吃掉上方卖单推涨停 | `launch_absorption_ratio` | `[t_start,t_detect]` 主动买量 / `t_start` 前有效卖单 |
| 3 分钟成交两亿 | `max_aggressive_buy_3m` | 任意 180 秒主动买量峰值（**必须**再除以 F/当日量/启动前卖量，绝对数不可跨股比） |
| 涨停后自挂自吃、窄幅震荡 | `churn_proxy` | 窄价带成交量极大但净价移很小 + 秒级双边补单（文案写「疑似对敲式换手代理」） |
| 护盘：吃买一留一层再吃 | `buy_refill_float_ratio` | 同价买单耗尽后 3s 内新增买量 / F（冰山补单代理） |
| 底部承接 | `low_band_sell_absorption_ratio` | 当日价格区间底部 20% 的主动卖量 / 全日主动卖量 |
| 盘口失衡 | `median_order_book_imbalance` | 十档 `(BidQty-AskQty)/(BidQty+AskQty)` 中位数 |

主动买卖方向**依赖成交文件的 aggressor 标志**；缺失时**不得**用价格涨跌机械替代，相关因子置空并降置信。

## 6. 分级与评分（记住：LV2 排序当前反向）

规则分级（阈值是研究起点，须样本外验证后再动）：

| 等级 | 条件 |
|---|---|
| `watch` | 过底部筛选 + 发生有效启动 |
| `medium` | `gross_ratio ≥ 5%` 或 `persistent_share ≥ 5%`，且数据完整 |
| `high` | `gross_ratio ≥ 10%` **且** `active_ratio ≥ 2%` **且** `persistent_share ≥ 5%` **且** `sell_cancel_ratio ≤ 50%` |
| `invalid` | 数据不全 / 流通股本失真 / 启动失败 / 巨量冲高回落 / 硬风险 |

评分**分三块保留，不要黑盒总分**：`total = 45%·dormancy + 20%·trigger + 35%·lv2`。
LV2 原始值先转**当日横截面百分位**再进模型；**方向从版本化 `lv2_score_model.json` 加载，不写死「越大越好」**。

> 原型 v2 留出结论：总卖单上界、有效卖单、撤单率、Delta、大单净流**越低**，未来排序反而越好——更像涨停日拥挤/派发，而非吸筹。这与视频直觉相反，必须尊重数据。

## 7. 买入 / 退出（不因「主力成本在底部」而放弃止损）

- **可成交时点**：收盘后归档数据最早 `T+1`；实时流最早晚于 `t_detect`。绝不按启动前价回填。
- **默认执行 = 回踩确认**，不追涨停瞬间：`T+1~T+5` 回踩、收盘仍在启动前箱体上沿或启动日 VWAP 上、回踩量 < 启动日 50%、未破启动日最低、次日高开 > 7% 不追。
- **退出**：硬止损（破启动日最低 或 -8%，先触发者）；结构止损（回箱体连续两日收不回）；+15% 移动止盈 / +25% 分批；10 日未新高时间止损；最长持有 15 日。
- **仓位**：单票风险 ≤ 组合 0.5%，单票 ≤ 5%，同业 ≤ 20%；一字板/无量/冲击成本过大跳过。`high` 只决定是否入候选，**不线性放大仓位**，直到样本外证明分数单调。

## 8. 回测：防未来函数 + 分开评估「筛选」与「排序」

- 底部池只用 `T-1`；启动前因子只读 `≤ t_start`；成交不早于 `t_detect`；流通股本 point-in-time；保留退市/曾 ST 避免幸存者偏差。
- walk-forward 按日期滚动：前 3 个月选方向/阈值，之后逐月完全样本外；同一股票不同日期不得跨训练/测试拆分。
- **必须分别报告两件事**（原型已证明二者结论相反）：
  1. **筛选力**：躺平+涨停 vs 纯躺平池 vs 非躺平涨停（用随机抽样检验 + Wilson 区间）；
  2. **排序力**：`score` 的 Spearman、高中低分组收益单调性。
- 指标：3/5/10/15 日收益及超额、胜率、盈亏比、MFE/MAE、回撤，全部**扣佣金/印花税/滑点/涨跌停不可成交**后再看。

## 10. 最小可行实现顺序（建议直接照做）

1. **`lifecycle.py` + 单测优先**：SZ（委托新增 / 成交 `C` 撤单 / 双边 FILL）与 SH（`A`/`D`）两条生命周期，同毫秒按 seq 稳定排序，`remaining` 恒等式。逐笔回放到 `t_start` 的结果，必须与「截断原文件到 `t_start` 后离线重算」**逐股一致**——这是整套东西正确性的地基。
2. 把固定 `13:20` 换成动态 `t_start`/`t_detect`，固定口径仅留作对照字段。
3. 三层卖单暴露 + 数据质量报告（未知关联/负剩余/快照断档）。
4. 接入 point-in-time 流通股本 / ST / 涨跌停规则。
5. 多月 walk-forward，冻结样本外月份验收，**筛选力与排序力分开结论**。
6. 只有多个市场阶段都稳定提升，才进模拟盘；模拟通过再谈自动执行。

---

## 11. 一句话总结

**能实现，但产出叫「控盘代理 / 异常订单流信号」，不叫「已确认主力控盘」。**
真正有工程价值、且被现有样本支持的是**「底部僵化 + 首次有效启动」的候选筛选**；`10%` 卖单是宽松上界、`LV2 综合排序当前反向`——这两点必须写进代码注释和界面文案，避免把叙事当事实。本方案不构成投资建议。
