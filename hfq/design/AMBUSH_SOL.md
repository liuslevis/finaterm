# AMBUSH：底部主力进场识别策略设计

> 状态：设计稿  
> 数据范围：沪深 A 股日线、流通股本、Level-2 逐笔委托、逐笔成交、十档行情快照  
> 目标：将“底部僵化股票突然启动、启动前存在大量稳定卖单”的视频思路转化为可复现、可回测、无未来函数的研究策略

## 1. 结论先行

这套方法可以实现，但必须把视频中的叙事拆成三个不同问题：

1. **标的是否处于低活跃底部**：用信号日前的日线、成交量和换手率判断。
2. **当日是否发生有效启动**：用涨停触达、滚动收益、量能和主动买入识别启动起点 `t_start`，并记录信号实际可确认的 `t_detect`。
3. **启动前卖单是否呈现集中、持续、低撤单特征**：用委托号重建订单生命周期，估算挂单暴露，而不是直接认定账户身份。

逐笔数据没有账户、席位或投资者身份，因此不能证明：

- 多笔委托属于同一个“主力”；
- 某笔卖单是主力持仓；
- 买卖双方是同一账户；
- “自己挂自己吃”或操纵行为真实发生。

所以系统输出应命名为**控盘代理信号**或**异常订单流信号**，不能输出“已确认主力控盘”。视频中“启动前卖单总量 / 流通股本 ≥ 10%”最多是一个宽松上界，因为总卖单可能包含撤单、同一资金重复挂单、普通投资者挂单以及已成交后再次挂出的股份。

本项目现有 `predictor\ambush\strategy.py` 已实现基础版本，并完成 2026-09-01 至 2026-09-11 的多日研究。已有结果说明：

- “躺平后触达涨停”的候选筛选在短周期内有一定研究价值；
- 原始“卖单越多、主动买入越强越好”的 LV2 排序在样本外并不稳定；
- 过大的卖单、撤单、主动买入 Delta 和大单净流入有时反而代表拥挤或派发；
- 因此 `10%` 不应作为单独买入条件，LV2 因子只适合作为候选内确认和排除依据。

## 2. 策略目标与非目标

### 2.1 目标

- 每个交易日从全市场生成“底部僵化池”。
- 在盘中或收盘后识别首次有效启动的股票。
- 精确重建启动前订单的新增、成交、撤单和剩余数量。
- 输出可解释的证据链、置信等级和失效原因。
- 支持事件回测、逐笔复盘和信号参数版本管理。
- 严格保证某时刻的信号只使用该时刻已经可见的数据。

### 2.2 非目标

- 不识别真实账户、营业部或资金主体。
- 不把总挂单量直接当作实际持仓量。
- 不以疑似对倒或操纵作为事实结论。
- 不因“主力亏得更多”而取消止损；大资金同样可能止损、做 T、对冲或提前持有更低成本筹码。
- 第一阶段不自动下单，只生成研究信号和复盘材料。

## 3. 数据输入

### 3.1 必需数据

| 数据 | 必需字段 | 用途 |
|---|---|---|
| 日 K | 日期、前复权 OHLC、成交量、成交额、换手率 | 底部与活跃度筛选、事件收益 |
| 证券主数据 | 代码、名称、板块、上市日期、ST 状态、流通股本 | 涨跌停规则、排除项、比例计算 |
| 逐笔委托 | 时间、交易所序号、买卖方向、价格、数量、操作类型 | 订单创建与撤单 |
| 逐笔成交 | 时间、成交序号、价格、数量、BS 标志、买卖委托号、成交代码 | 成交归因、订单消耗、主动方向 |
| 十档快照 | 时间、最新价、累计成交、买卖十档价量 | 启动识别、盘口失衡、结果校验 |

现有 Wind CSV 的价格单位为“元 × 10000”，时间为 `HHMMSSmmm`，编码为 GBK。解析后应立即统一为：

```text
price: decimal yuan
qty: integer shares
time: exchange-local timestamp with millisecond precision
side: B | S
event_type: ADD | FILL | CANCEL
order_id: exchange order sequence
```

### 3.2 市场差异

- **深交所**：新增委托来自 `逐笔委托.csv`；撤单通常是 `逐笔成交.csv` 中成交代码 `C`，通过买方或卖方委托号关联。
- **上交所**：新增和撤单都可能在 `逐笔委托.csv` 中，通过类型 `A` / `D` 区分；成交文件用于扣减订单剩余量。
- 所有事件必须按交易所序号排序；时间只用于展示和区间查询，不能在同毫秒事件之间替代序号排序。
- 订单剩余量必须满足 `remaining = max(original_qty - filled_qty - canceled_qty, 0)`；若出现负值、孤立撤单或不存在的委托号，应记录数据质量错误，不能静默修补。

### 3.3 外部静态数据

流通股本必须使用**信号日当时可知**的值，并按除权、送转、增发和限售股解禁日期维护时点版本。若流通股本缺失或非正数：

- 仍可计算绝对订单流指标；
- 所有占流通股比例字段返回空值；
- 禁止给出 `CONTROL_CONFIRMED`；
- 不得以总股本或当前最新流通股本静默代替。

## 4. 整体流程

```text
全市场证券
  -> 合规与数据完整性过滤
  -> T-1 日收盘后的底部僵化池
  -> T 日启动检测，得到动态 t_start 与 t_detect
  -> 仅对命中标的加载完整 LV2
  -> 重建截至 t_start 的订单生命周期
  -> 计算卖单暴露、持续性、撤单、成交吸收、补单、盘口因子
  -> 规则门槛 + 横截面评分
  -> watch / medium / high / invalid
  -> T+1 或回踩确认后的可交易事件
```

采用两阶段架构是为了避免每天解压全市场全部逐笔数据：

1. 日线预筛只读取全市场低频数据。
2. 仅对“底部池 ∩ 当日启动”的少量股票读取 Level-2。

## 5. 第一阶段：底部僵化池

所有指标只使用信号日 `T` 之前的数据，最后一根可用 K 线必须是 `T-1` 或更早。

### 5.1 硬过滤

- A 股普通股票，排除 ST、退市整理、长期停牌和上市不足 120 个交易日的标的。
- 最近 20 日有效交易日不少于 18 日。
- 最近 20 日平均成交额达到可交易下限，默认 `≥ 2000 万元`，避免买入后无法退出。
- 信号日前 20 日不得已经出现同类有效启动；第一版使用“20 日内触及涨停次数 ≤ 1”。

### 5.2 底部指标

| 指标 | 公式 | 默认门槛 |
|---|---|---:|
| 240 日价格位置 | `(close[T-1] - low_240) / (high_240 - low_240)` | `≤ 40%` |
| 60 日区间振幅 | `high_60 / low_60 - 1` | `≤ 40%` |
| 20 日平均绝对收益 | `mean(abs(close.pct_change()))` | `≤ 2.5%` |
| 20 日平均换手率 | `mean(turnover_20)` | `≤ 2.5%` |
| 近期缩量比 | `mean(volume_20) / median(volume_120)` | 优先 `< 0.8` |
| 20 日最大单日涨幅 | `max(return_20)` | 默认 `< 5%` |

“日均涨幅不超过 5%”不能直接使用有正有负的平均收益，否则涨跌会相互抵消。实现中同时保留：

- `mean_abs_return_20d_pct`：衡量股性是否僵化；
- `max_positive_return_20d_pct`：排除近期已经反复活跃的股票。

### 5.3 躺平分

硬门槛用于保证语义，横截面分数用于排序：

```text
dormancy_score =
    30% * low_price_position_rank
  + 20% * low_60d_range_rank
  + 20% * low_abs_return_rank
  + 15% * low_turnover_rank
  + 15% * low_recent_volume_rank
```

所有排名在同一信号日的候选中计算百分位，低值更好的指标先反向。不得跨日期直接比较原始量级。

## 6. 第二阶段：启动事件与动态时间点

视频案例使用固定 `13:20`，但其他股票的启动时间不同。生产实现必须动态检测启动点；固定时间只作为复盘参数。

### 6.1 启动条件

按 1 分钟聚合逐笔成交或行情快照，某分钟同时满足以下条件时记为候选启动：

- 从昨收到当前的涨幅达到所属板块涨停幅度的 `70%`，或 3 分钟收益 `≥ 3%`；
- 最近 3 分钟成交量 `≥` 过去 20 个有效分钟中位数的 `8 倍`；
- 最近 3 分钟主动买入量占比 `≥ 60%`；
- 最近 3 分钟成交量 `≥` 当日前一时刻累计成交量的 `10%`；
- 价格创当日新高。

定义两个时间：

- `t_detect`：首个完整滚动窗口满足全部启动条件的窗口结束时刻，也是实时系统最早可以发出信号的时刻；
- `t_start`：该窗口内价格和成交量开始突变的分钟起点，用作“启动前订单”的统计截止点。

`t_start` 可以在 `t_detect` 时回看已经发生的三分钟确定，但交易和回测成交不得早于 `t_detect`。若只有日线数据，允许使用“触达涨停价”作为离线候选条件，但加载 LV2 后必须补算两个时间点。

### 6.2 涨停触发

- 主板普通股通常按 10%；
- 创业板、科创板通常按 20%；
- ST、特殊上市阶段和交易规则变化必须由证券主数据按日期给出，不能仅靠代码永久硬编码；
- 涨停价按交易所最小价格单位和舍入规则计算；
- 使用最高价触达涨停，不要求收盘封板。

### 6.3 启动质量

记录但不直接作为主力证据：

```text
trigger_score =
    35% * event_volume_ratio_rank
  + 25% * max_3m_aggressive_buy_ratio_rank
  + 20% * price_acceleration_rank
  + 20% * low_pre_event_turnover_rank
```

若 `t_start` 出现在 09:25 集合竞价成交附近，应单独分类为 `AUCTION_TRIGGER`，不能与连续竞价三分钟拉升混算。

## 7. 第三阶段：订单生命周期重建

### 7.1 核心结构

```python
OrderState = {
    "order_id": int,
    "side": "B" | "S",
    "price": float,
    "created_at": int,
    "original_qty": int,
    "filled_qty": int,
    "canceled_qty": int,
    "remaining_qty": int,
    "last_event_at": int,
    "status": "OPEN" | "PARTIAL" | "FILLED" | "CANCELED",
}
```

同一订单不会在价格之间“移动”；改变价格意味着撤掉旧订单并提交新订单。因此视频中的“挂单位置几乎不动”在算法中应解释为：

- 相同价格带持续存在大量剩余卖量；
- 组成该价格带的订单寿命较长；
- 旧订单被成交或撤掉后，相同价格在短时间内被新订单补回；
- 价格带相对当时市场价格长期保持在上方。

### 7.2 截止时刻

所有启动前指标的截止时刻为动态 `t_start`，计算动作发生在 `t_detect`。为测试视频原逻辑，同时输出固定 `13:20:00.000` 口径，但固定口径不得参与实时信号，也不得用于早于 13:20 启动的样本。

### 7.3 三层卖单暴露

设流通股本为 `F`：

1. **总卖单暴露上界**

   ```text
   gross_sell_qty = sum(original_qty of sell orders created_at <= t_start)
   gross_sell_float_ratio = gross_sell_qty / F
   ```

   这是最接近视频“1.76 亿卖单”的口径，也是最容易重复计算的宽松上界。

2. **截点有效卖单**

   ```text
   active_sell_qty =
       sum(remaining_qty at t_start for sell orders created_at <= t_start)
   active_sell_float_ratio = active_sell_qty / F
   ```

   它排除了 `t_start` 前已成交和已撤掉的数量，更适合描述启动前仍暴露在市场中的卖压。

3. **持续固定卖单**

   ```text
   persistent_sell_qty =
       sum(remaining_qty at t_start
           where original_qty >= 10,000
           and lifetime_at_t_start >= 30 minutes)
   persistent_sell_float_ratio = persistent_sell_qty / F
   persistent_sell_share = persistent_sell_qty / gross_sell_qty
   ```

   这是“剧本单”的可计算代理，但仍不能证明账户归属。

`10%` 门槛只能应用于 `gross_sell_float_ratio` 并标注为 `gross_proxy_pass`。高置信信号还必须要求有效量、持续量和低撤单率支持，不能只看总量。

## 8. Level-2 因子

### 8.1 挂单真实性

| 字段 | 定义 | 解释 |
|---|---|---|
| `sell_fill_ratio` | `t_start` 前卖单成交量 / 总卖单量 | 挂单是否实际被市场消化 |
| `sell_cancel_ratio` | `t_start` 前卖单撤单量 / 总卖单量 | 过高可能是展示性挂单 |
| `persistent_sell_share` | 持续卖单 / 总卖单 | 上方卖单是否长期存在 |
| `active_to_gross_ratio` | 截点有效卖单 / 总卖单 | 排除大量重复挂撤后的膨胀 |
| `sell_refill_ratio` | 同价订单耗尽后 3 秒内新增卖量 / 流通股本 | 卖墙是否持续补充 |

### 8.2 启动吸收

- `max_aggressive_buy_3m`：任意连续 180 秒内主动买成交量最大值。
- `launch_absorption_ratio`：`[t_start, t_detect]` 中主动买入量 / `t_start` 前有效卖单量。
- `launch_price_efficiency`：三分钟价格涨幅 / 三分钟成交量占流通股比例；区分有效拉升和巨量滞涨。
- `time_to_limit_seconds`：从 `t_start` 到首次触及涨停的秒数。
- `limit_seal_ratio`：首次封板后封单量 / 流通股本。
- `open_board_count`：首次封板后的开板次数。

“三分钟成交两亿”应同时除以流通股本、事件日成交量和启动前有效卖量，绝对数量不能跨股票比较。

### 8.3 成交与盘口

- `delta_ratio = (aggressive_buy_qty - aggressive_sell_qty) / trade_qty`。
- `large_order_net_flow_ratio`：以当日成交量 95 分位数定义大单，计算大单主动净流。
- `stacked_buy_imbalance_levels`：相邻价位中买方成交量至少为卖方三倍的最长连续层数。
- `low_band_sell_absorption_ratio`：当日价格区间底部 20% 中主动卖出量 / 全日主动卖出量。
- `buy_refill_float_ratio`：同价买单耗尽后 3 秒内新增买量 / 流通股本，作为冰山补单代理。
- `median_order_book_imbalance`：十档 `(BidQty - AskQty) / (BidQty + AskQty)` 的中位数。
- `post_launch_churn_ratio`：启动后三分钟成交量 / 同期价格净位移，用于识别巨量但价格不动。

主动买卖方向依赖数据源 BS 标志。若该字段缺失，不得用价格涨跌机械替代；相关因子应为空并降级置信度。

### 8.4 疑似“自挂自吃”

没有账户标识时只能输出 `churn_proxy`，其条件可以包括：

- 同一窄价带内成交量极大但净价格位移很小；
- 买卖两侧在秒级同时快速补单；
- 大量订单短寿命、成交后迅速在同价补回；
- 成交 Delta 很大但盘口净变化与价格响应弱。

界面文案必须写“疑似对敲式换手/高频换手代理”，不得写“主力自买自卖”。

## 9. 信号判定

### 9.1 规则层

默认状态机：

```text
DORMANT
  -> TRIGGERED          底部池内发生有效启动
  -> CONTROL_CANDIDATE  卖单暴露与持续性通过
  -> RETEST_READY       启动后缩量回踩且结构未破坏
  -> ENTERED            满足执行规则
  -> INVALID            任一硬失效条件触发
```

建议分级：

| 等级 | 条件 |
|---|---|
| `watch` | 通过底部筛选并发生有效启动 |
| `medium` | `gross_sell_float_ratio ≥ 5%` 或 `persistent_sell_share ≥ 5%`，且数据完整 |
| `high` | `gross_sell_float_ratio ≥ 10%`、`active_sell_float_ratio ≥ 2%`、`persistent_sell_share ≥ 5%`、`sell_cancel_ratio ≤ 50%` 同时成立 |
| `invalid` | 数据不完整、流通股本失真、启动失败、巨量冲高回落或硬风险条件触发 |

门槛是初始研究值，必须通过滚动样本外验证后再调整。

### 9.2 评分层

底部、触发和 LV2 分数必须分别保留，不能只输出一个黑盒总分：

```text
total_score =
    45% * dormancy_score
  + 20% * trigger_score
  + 35% * lv2_confirmation_score
```

LV2 原始值先在**同一交易日的候选横截面**内转为百分位。模型配置必须包含：

- 版本号；
- 训练起止日期；
- 训练样本量和日期数；
- 字段方向与权重；
- 训练数据截止日期；
- 样本外评估结果。

仓库现有 v2 研究模型显示，较低的总卖单暴露、有效卖单暴露、撤单率、Delta 和大单净流，以及较高的买单补单和 OBI，在留出样本中排序更好。这与视频直觉部分相反，所以正式实现不能写死“越大越好”，应从版本化模型加载方向。

## 10. 买入与退出设计

### 10.1 可执行时点

如果使用收盘后归档数据，最早只能在 `T+1` 交易，绝不能按 `T` 日启动前或启动价回填成交。若实现实时流式版本，最早成交时间也必须晚于 `t_detect`，且只有在当前时刻已完成的事件才可参与计算。

不建议在启动涨停瞬间追入。默认执行为启动后的回踩确认：

- `T+1` 至 `T+5` 内回踩；
- 收盘价仍在启动前底部箱体上沿或启动日 VWAP 之上；
- 回踩日成交量低于启动日的 50%；
- 未跌破启动日最低价；
- 回踩期间没有连续两日大幅主动卖出或卖墙撤单；
- 次日开盘涨幅高于 7% 时不追入。

入场价格使用次日开盘价、VWAP 或规则触发后的下一根 bar 成交价，并计入滑点和涨跌停不可成交约束。

### 10.2 退出

初始研究规则：

- 硬止损：收盘跌破启动日最低价或入场价 `-8%`，取先触发者；
- 结构止损：回到启动前箱体且连续两日无法收复；
- 止盈：`+15%` 后移动止盈，或 `+25%` 分批退出；
- 时间止损：入场后 10 个交易日未创新高；
- 最长持有：15 个交易日。

这些规则必须独立回测。不能因为推定“主力成本在底部”而忽略价格止损，因为真实主体、成本和库存都不可见。

### 10.3 仓位

- 单票风险预算不超过组合净值的 0.5%；
- 单票仓位上限默认 5%；
- 同行业信号合计上限 20%；
- 一字涨停、无合理成交量或预估冲击成本过高时跳过；
- `high` 只影响是否进入候选，不直接线性放大仓位，直到样本外验证证明分数具有稳定单调性。

## 11. 回测设计

### 11.1 防止未来函数

- 底部池只使用 `T-1` 及以前数据。
- `t_start` 前订单指标只能读取截至 `t_start` 的事件；启动窗口指标只能读取截至 `t_detect` 的事件；任何模拟成交不得早于 `t_detect`。
- 流通股本按公告生效日做 point-in-time 查询。
- 退市股票、历史 ST、停牌和曾经上市标的必须保留，避免幸存者偏差。
- 前复权价格用于收益连续性，成交价格和涨跌停判断使用当日真实未复权价格。
- 当日横截面排名只能使用当日已经命中的候选；实时模式不得提前知道收盘后的完整候选集合。

### 11.2 样本划分

采用按日期滚动的 walk-forward：

1. 至少收集 6 个月、覆盖不同市场环境的信号。
2. 前 3 个月仅用于因子方向和阈值选择。
3. 后续每个月只用此前数据训练，在下个月完全样本外验证。
4. 参数每月最多更新一次，保存模型版本。
5. 单只股票不同日期的事件不能随机拆到训练集和测试集两侧。

现有 2026-09-01 至 2026-09-11 共 99 个候选、留出集 23 个样本，只能视为原型验证，不能支持稳定实盘结论。

### 11.3 对照组

必须同时报告：

- 全部底部僵化股；
- 底部僵化但未启动；
- 非底部但触达涨停；
- 底部启动但未通过 LV2；
- 底部启动且通过 LV2；
- 按行业、市值和当日涨幅匹配的对照组。

这样才能区分收益来自“涨停效应”“低位反转”还是 LV2 证据。

### 11.4 指标

- 3、5、10、15 个交易日收益及相对沪深 300 超额收益；
- 胜率、平均值、中位数、盈亏比；
- 最大有利/不利变动 MFE、MAE；
- 最大回撤、收益波动、换手率；
- Spearman 排序相关；
- 高中低分组收益单调性；
- 95% Wilson 胜率区间；
- bootstrap 收益置信区间；
- 按日期聚类的显著性检验；
- 扣除佣金、印花税、滑点和涨跌停不可成交后的结果。

若高分组没有稳定优于低分组，分数只能用于解释，不得用于仓位排序。

## 13. 数据质量与异常处理

每只股票每天生成质量报告：

- 委托号唯一性与重复数；
- 成交关联到未知委托号的比例；
- 撤单关联失败比例；
- 订单出现负剩余量的数量；
- 行情快照最大间隔；
- 逐笔累计成交量与行情累计成交量偏差；
- 价格单位和时间范围检查；
- 流通股本日期与来源；
- 交易所事件排序是否单调。

硬性降级条件：

- 未知订单关联量超过总成交量 1%；
- 快照中断超过 60 秒；
- 逐笔成交量与行情累计成交量偏差超过 1%；
- 流通股本缺失；
- `t_start` 前三十分钟数据不完整。

降级时保留复盘数据，但不产生 `high` 信号。

## 14. 测试与验收

### 14.1 单元测试

- 深交所新增、部分成交、完整成交、撤单生命周期。
- 上交所 `A` / `D` 生命周期。
- 同毫秒不同序号的稳定排序。
- 午间休市、集合竞价、涨停价和最小价格单位。
- `t_start` 指标不读取启动后的事件，`t_detect` 只读取已经结束的启动窗口。
- 总卖单、有效卖单和持续卖单公式。
- 流通股本缺失时比例为空且信号降级。
- 同价 3 秒补单边界。

### 14.2 数据回放测试

选取至少以下人工标注案例：

- 视频式“启动前卖墙稳定、三分钟拉升”；
- 大量挂单随后撤掉的诱导型案例；
- 正常活跃股的大量自然委托；
- 一字涨停；
- 集合竞价启动；
- 冲板后快速炸板；
- 没有 BS 标志或快照缺口的降级案例。

逐笔回放到 `t_start` 时，启动前指标必须与截断原文件至 `t_start` 后离线重算完全一致；回放到 `t_detect` 时，触发结果必须与截断至 `t_detect` 后重算一致。

### 14.3 第一阶段验收标准

- 给定日期，能在不解压全市场全部逐笔文件的情况下生成候选。
- 每个候选都能展示 `t_start`、`t_detect` 及触发它的原始成交窗口。
- 任意卖单都能追踪到新增、成交、撤单和剩余量。
- `gross / active / persistent` 三种口径可由原始记录复算。
- 信号输出包含等级、原因、数据质量、模型版本，而非只有一个分数。
- 回测结果明确区分筛选效果与排序效果，并包含交易成本和不可成交约束。
- 任何页面和导出均不把代理指标描述成真实主力持仓或账户级事实。

## 15. 实施顺序

1. 从 `predictor\ambush\strategy.py` 抽出订单生命周期和因子计算，补齐类型与测试。
2. 将固定 13:20 改为动态 `t_start` / `t_detect`，固定口径仅保留为对照字段。
3. 接入时点化流通股本、ST 和涨跌停规则。
4. 生成三层卖单暴露与数据质量报告。
5. 在现有委托地图中增加 `t_start`、`t_detect` 和证据卡。
6. 建立多月 walk-forward 回测，在冻结的样本外月份验收。
7. 只有在不同市场阶段都观察到稳定提升后，才将信号用于模拟盘；模拟盘通过后再讨论自动执行。

## 16. 风险声明

该策略研究的是公开行情中的订单流形态，不识别真实交易主体。挂单可以撤销，逐笔委托可以重复，历史表现可能来自涨停、低位反转或小市值风格暴露。任何“主力”“控盘”“护盘”“对倒”均只能作为便于理解的市场叙事，系统事实层必须使用“卖单暴露”“持续订单”“补单”“成交吸收”等可验证术语。本设计不构成投资建议。
